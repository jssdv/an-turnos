# CLAUDE.md

**An** — a web app (Spanish UI) for clinics: FastAPI API over one SQLite file (`an/web/`), delivered as a single portable app (`deploy/An-mac.command`, Windows exe via `.github/workflows/entregable.yml`; there is no server mode: the Postgres/Docker server stayed in git tag `servidor-postgres-final`), a React front (`web/`) and a pure Python core with one area per service: **Radiología** (monthly roster → weekly assignment workbook) and **Turnos** (shift grid with OR-Tools CP-SAT, posts, hours and Colombian surcharges; generic: the name of each area is data in `area.nombre`, never code). Used by non-technical coordinators. The former PySide6 desktop app was removed on 26/10/2026 (git tag `qt-final`). Remote: `origin` = `jssdv/an-turnos`.

Web direction (progress checklist and per-phase task plans): `docs/PLAN_WEB.md`, `docs/superpowers/plans/`. Resume a phase from the first unchecked `- [ ]`.

Architecture: `docs/ARQUITECTURA.md`. Roadmap toward a full scheduling system: `docs/PROYECTO.md` (Radiología stages) and `docs/VISION.md` (multi-service). Each new stage gets its own design doc in `docs/` before coding.

## Commands
- Dev env: `python3 -m venv .venv && .venv/bin/pip install -r requirements.txt -r requirements-dev.txt -r requirements-web.txt`.
- Radiología CLI: `.venv/bin/python -m an.radiologia.generar_semana "<mensual>.xlsx" YYYY-MM-DD [salida.xlsx]` (date = Monday).
- Tests: `.venv/bin/python -m pytest tests --ignore=tests/turnos/test_turnos.py` (each file also runs as a script and prints `OK`); `tests/turnos/test_turnos.py` takes ~2 min (solves full months); `tests/radiologia/test_generar_semana.py` is a script without `test_*` functions: run it with `.venv/bin/python`.
- Front web (`web/`, Vite + React 19 + TS + Tailwind v4 + Untitled UI/React Aria; components copied from `untitleduico/react@1d410cb` into `web/src/components/` keeping their paths, only those in use; `@/` = `web/src`): `cd web && npm ci && npm run dev` (proxy `/api` → `127.0.0.1:8000`; API con `AN_ORIGEN=http://localhost:5173`); `npm run build` (incluye `tsc`); `npm run tipos` regenera `src/api/esquema.d.ts` desde la API (`PYTHON=…/python PYTHONPATH=..`); `VITE_TRABAJOS_SIMULADOS=1` simula `generar`/`trabajos` hasta que exista la Fase 3; datos de prueba: `python web/sembrar_demo.py`. Check: `python checks/diseno.py` (sin colores literales fuera de `tokens.css` y `styles/theme.css`, texto ≥ 11 px, contraste 4,5:1; ignora `web/src/components/`).
- Web demo in one command: `web/demo.sh` (SQLite demo data in `web/.demo/` + API with its worker + Vite; login `editor@demo.co` / `clave-larga-1`; Ctrl+C stops all).
- CI (`.github/workflows/ci.yml`) sets `AN_TIEMPO_ESCALA=3` (multiplies the solver time limits in `test_turnos.py`); set it locally too if solver tests time out on a slow machine.
- Portable app (`an/web/entregable.py`; data in `AN_DATOS` or `%LOCALAPPDATA%/AnTurnos/an.db`, backups at open/close): API and solver worker (queue = table `trabajo`, `an/web/trabajador.py`) run in one process. `an/web/sqlite_pg.py` is the SQLite adapter that speaks the `%s`/`cursor()` style the web layer was written in (so the routes keep that SQL); `an/turnos/puente.py` bridges `BD` (`?`) to it (`BD.web(Conexion(c))`). One clinic and one area per database. Schema: `an/web/esquema_sqlite.sql` (version 12) + numbered files in `an/web/migraciones_sqlite/` from 013 (`PRAGMA user_version`; a published migration is never edited). Admin CLI: `AN_BASE=<an.db> .venv/bin/python -m an.web.admin crear-clinica|crear-area|crear-usuario|dar-permiso`; worker alone: `AN_BASE=… python -m an.web.trabajador` (`AN_SOLVER_WORKERS` = CP-SAT threads, default min(8, cores); `checks/medir_solver.py` times a month). Radiología web: `crear-area --tipo radiologia`; cuadro mensual en la tabla `archivo` vía `POST /api/areas/{area}/archivos?nombre=x.xlsx` (cuerpo crudo, ≤ 10 MB) y análisis en `/api/areas/{area}/archivos/{id}/semanas/{lunes}` (`an/web/rutas_radiologia.py`, llama a `an/radiologia/`). Exports: `POST/GET /api/areas/{a}/periodos/{p}/exportes` (+ `/{id}/descargar`) store xlsx in table `exporte` (`an/web/rutas_exportes.py`, `tests/web/test_exportes.py`). `tests/web` runs on a throwaway SQLite file (`tests/web/fixtura_api.py`). Checks: `python checks/tokens.py --verificar`, `checks/reglas.py`, `checks/diseno.py`.
- Delivery: push to `main` triggers `entregable.yml` (PyInstaller zip for Windows). After every feature: rebuild `web/dist` (`cd web && npm run build`; it is not in git and the Mac launcher serves it) and check the bundle contains the new UI text.

## Layout
- `an/nucleo/xlsx.py` — `poner_texto`, shared by the xlsx exports.
- `an/web/` — API (routes `rutas_*.py`, auth, `sqlite_pg.py` adapter, `esquema.py`/`migraciones_sqlite/`), solver worker `trabajador.py`, admin CLI, `entregable.py` (portable launcher). `web/` — React front; colors come from FigCraft (`docs/diseno/An_UI.figcraft`) via `checks/tokens.py` → `web/src/tokens.css`.
- `an/radiologia/` — `generar_semana.py` (core), `analisis.py` (pure functions), `plantilla_semana.xlsx`.
- `an/turnos/` — pure core (`dominio`, `db`, `puente`, `reglas`, `solver`, `demanda`, `dotacion`, `puestos`, `capacitacion`, `recargos`, `flujo`, `cambios`, `solicitudes`, `analitica`, `exportar`). Imports inside the package are relative. `BD` works on a SQLite file/memory (core tests) and, through `BD.web`, on the web layer's connection.
- `tests/<área>/`, `tests/web/`, `tests/checks/`, `ejemplos/radiologia/`, `docs/`.

## Radiología: roster requirements / agreed rules
See `docs/RADIOLOGIA.md` for the architecture notes. Essentials:
- Row 3 of `Cambios …` must hold full dates (format `d`); weeks are matched by exact date. Values are read with `data_only=True`, so the roster must have been saved by Excel.
- Contingencia, vacaciones, asignación de estudios and free-text notes stay blank (manual); full names everywhere; densitometría includes Sunday; `Z` and hemodinamia are not published. Unknown shift codes are reported, not published.
- Keep Spanish sheet names, headings and labels exactly as written. `~$…xlsx` are Excel lock files: ignore.

## Turnos: agreed rules
- Pure core; the web calls it and the solver runs in the worker (`an.web.trabajador`). `asignacion` has two versions per month: `original` (published) and `cambios` (working copy; manual edits are `fijo`).
- Per-area toggle `usa_puestos` (parámetro, default on; pantalla «Requerimiento», que también aloja la tabla de Turnos). Off: need = people per turno window (`inicio`–`fin` of each active solver turno; same-hours turnos share a row; overlapping windows add) and weekday (0–6, `F` festivo), stored as `demanda` rows with `puesto_id=0` and `tipo_dia` `"0"`…`"6"`/`"F"` (`demanda._tipos`); no post split (`asignar_tramos` leaves everyone in apoyo). On: each post has the same turno × weekday matrix (`GET/PUT /puestos/{id}/requerimiento`, checkbox per post = deseable; legacy `LS`/`DF` rules read as days 0–5 and 6+`F`); a cell can fix its post (table `puesto_fijo`, respected by `asignar_tramos`); permuta moves turno+post, ajuste can change only the post; `cambio_turno.celdas` rows are `[colab, fecha, antes, después, puesto_antes, puesto_después]` (old 4-field rows still read).
- Generar `modo` `desde` (+ `desde` fecha dentro del periodo): rehace solo los días ≥ fecha en `cambios`; antes de la fecha cuadro y puestos quedan fijos, `fijo=1` posteriores se respetan, y rigen todos los parámetros del área (`flujo.preparar`).
- Parámetro `partir_corridos` (0/1, default 1 en áreas nuevas; el núcleo sin parámetro usa 0): con 1, `asignar_tramos` corta cada corrido (C) en su punto medio y castiga (`W_PARTIR_P`) repetir el mismo puesto en las dos mitades (M y T). Parámetro `peso_corrido` (0–10, default 1): costo `W_C` × peso por cada corrido en el solver (0 = sin costo); `max_c_semana` y `max_c_seguidos` siguen siendo topes duros.
- Reasignar puestos: `POST /api/areas/{a}/periodos/{id}/reasignar-puestos` (cuerpo `{desde?}`, If-Match; botón «Reasignar puestos» en el cuadro) rehace solo puestos y capacitación con el cuadro de turnos actual (`flujo.recalcular`), respetando `puesto_fijo`; con `desde` lo anterior no cambia.
- Eliminar periodo: `DELETE /api/areas/{a}/periodos/{id}` con `If-Match`; solo periodos abiertos y sin trabajo en cola; borra cuadro, puestos, cambios, exportes y trabajos del periodo.
- Coverage comes from posts' demand rules (default seed: 4 day posts + Guardia noche ×2 Mon–Sat; Autoclave and Lavado + guardia on Sun/holiday; Ropa desirable). Restricted person: no nights, only post 3. Refuerzo is outside the solver.
- Hours: art. 165 CST average over N weeks (default 3) vs 42 h/week; unpaid pauses don't count. Legal figures are editable data — confirm with RR. HH./legal. A new export replaces the previous one of the same type and a download deletes the stored file (no leftovers in `exporte`). The cuadro sheets carry a «Σ sem» weekly-hours cell after each Sunday; night and Sunday/holiday hours are reported separately and the solver minimizes the max–min of calendar hours on Sunday/holiday (`recargos.horas_df`, `W_DF_EQ`, compared among people with the same `pct`). Parámetro `max_horas_semana` (0 = off) is a hard cap of hours per full Mon–Sun week in the solver, with a warning in `reglas.validar`. Keep Spanish labels.
- Manual edits of the grid are audited: the UI asks permuta / cambio de servicio / ajuste and `cambios.py` writes `cambio_turno` (append-only; undo = anular) and `cambios.log`. Only permutas spend the per-person, per-period cupo `limite_permutas` (default 2; over it needs an approved exception). Undo/anular is all-or-nothing: if a cell was edited after the change, it refuses (`EditadoDespues`). After every manual change the UI lists only the *new* alerts (rules, coverage, posts left uncovered); it warns, never blocks.
- Personal requests (`solicitud` table, tab «Solicitudes»; types `libre` / `quiero` turno / `evitar` turno, priority normal/alta; `servicio` fixed `esterilizacion`) are registered by coordination only and are a **soft wish**: `solver.py` adds a per-day penalty (`solicitudes.W_SOL` 400 / 4000, below `W_FALTA`), never a hard constraint, so coverage and legal rules win. `solicitudes.evaluar` (pure) gives cumplida / parcial / no cumplida / fuera + a heuristic reason from the current grid; after generating, the UI lists up to 3 unmet.
- Analíticas section (read-only): `analitica.py` computes ausentismo, simultáneos, cobertura, cambios, horas extra (mes vs N semanas), recargos, equidad and banco de horas from existing tables (no migration); the UI only paints. Spec: `docs/superpowers/specs/2026-10-25-dashboard-analiticas-design.md` (all 3 deliveries done). «Costo» = horas equivalentes (there is no salary data); banco uses closed periods and movements only.
