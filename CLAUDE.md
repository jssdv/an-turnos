# CLAUDE.md

**An** — one desktop app (Spanish UI) with a shared core and one area per service: **Radiología** (monthly roster → weekly assignment workbook) and **Esterilización** (shift grid with OR-Tools CP-SAT, posts, hours and Colombian surcharges). The local user picked at startup decides the area. Used by non-technical coordinators on a locked-down Windows PC (no admin, no installs). Remote: `origin` = `jssdv/an-turnos`.

Web direction (progress checklist and per-phase task plans): `docs/PLAN_WEB.md`, `docs/superpowers/plans/`. Resume a phase from the first unchecked `- [ ]`.

Design of the core and how areas plug in: `docs/NUCLEO.md`. Roadmap toward a full scheduling system: `docs/PROYECTO.md` (Radiología stages) and `docs/VISION.md` (Esterilización / multi-service). Each new stage gets its own design doc in `docs/` before coding.

## Commands
- Dev env: `python3 -m venv .venv && .venv/bin/pip install -r requirements.txt` (or double-click `An.command`, which does it and opens the app).
- Run: `.venv/bin/python -m an [usuario]` (without a name it asks; users live in `usuarios.json`, created on first run, git-ignored).
- Radiología CLI: `.venv/bin/python -m an.radiologia.generar_semana "<mensual>.xlsx" YYYY-MM-DD [salida.xlsx]` (date = Monday).
- Tests (each prints `OK`): `tests/radiologia/test_generar_semana.py`, `tests/radiologia/test_gui.py`, `tests/esterilizacion/test_puestos.py`, `tests/esterilizacion/test_gui.py`, `tests/esterilizacion/test_cambios.py`, `tests/esterilizacion/test_solicitudes.py`, `tests/esterilizacion/test_analitica.py`, `tests/esterilizacion/test_turnos.py` (~2 min, solves full months), `tests/nucleo/test_nucleo.py`, `tests/nucleo/test_graficos.py`. GUI tests run offscreen (`QT_QPA_PLATFORM=offscreen`) and point `QSettings` at a temp ini so the user's saved settings are not touched; `Ventana(Area).grab()` gives screenshots.
- pytest (`requirements-dev.txt`): `.venv/bin/python -m pytest tests --ignore=tests/esterilizacion/test_turnos.py` runs the `test_*` files; `test_turnos.py` takes ~2 min. `tests/nucleo`, `tests/radiologia` and every `test_gui.py` are scripts that create a `QApplication` on import: run them with `QT_QPA_PLATFORM=offscreen .venv/bin/python <file>`.
- Postgres dev (web, `docs/PLAN_WEB.md`): `docker compose up -d db` (127.0.0.1:5433, db/user `an`, clave de desarrollo `an_dev`), `docker compose down`.
- Front web (`web/`, Vite + React 19 + TS): `cd web && npm ci && npm run dev` (proxy `/api` → `127.0.0.1:8000`; API con `AN_ORIGEN=http://localhost:5173`); `npm run build` (incluye `tsc`); `npm run tipos` regenera `src/api/esquema.d.ts` desde la API (`PYTHON=…/python PYTHONPATH=..`); `VITE_TRABAJOS_SIMULADOS=1` simula `generar`/`trabajos` hasta que exista la Fase 3; datos de prueba: `python web/sembrar_demo.py`. Check: `python checks/diseno.py` (sin colores literales fuera de `tokens.css`, texto ≥ 11 px, contraste 4,5:1).
- Web server (`docs/PLAN_WEB.md`): `.venv/bin/pip install -r requirements-web.txt`; `AN_PG_URL=postgresql://an:an_dev@127.0.0.1:5433/an` (see Postgres dev above); API: `.venv/bin/uvicorn an.web.app:crear_app --factory`; admin: `.venv/bin/python -m an.web.admin crear-clinica|crear-area|crear-usuario|dar-permiso`; migrations: `python -m an.web.esquema`; solver worker (queue = table `trabajo`): `.venv/bin/python -m an.web.trabajador` (same `AN_PG_URL`/`AN_ROL`; `AN_SOLVER_WORKERS` = CP-SAT threads, default min(8, cores); `checks/medir_solver.py` times a month); migrate a `turnos.db` into an empty area: `python -m an.web.migrar turnos.db --clinica N --area M` (one transaction, compares figures on both sides, exit ≠ 0 and rollback if any differ; `--solo-verificar` only compares). Core tests on PostgreSQL: prefix `AN_BD=postgres` (each `BD()` gets a throwaway schema); `tests/web` needs `AN_PG_URL`; exports: `POST/GET /api/areas/{a}/periodos/{p}/exportes` (+ `/{id}/descargar`) store xlsx in table `exporte` (`an/web/rutas_exportes.py`, `tests/web/test_exportes.py`). Checks: `python checks/tokens.py --verificar`, `checks/rls.py`, `checks/reglas.py`.
- Producción (Fase 8): `docker compose -f docker-compose.prod.yml --env-file .env up -d --build` (Caddy + API + trabajador + Postgres; `.env.example`); respaldo cifrado `deploy/respaldar.sh`, restauración `deploy/restaurar.sh`, prueba `checks/probar_respaldo.sh`; guía `docs/operacion.md`, seguridad `docs/seguridad.md`, hallazgos `docs/seguridad-hallazgos.md`.
- Windows zip: `./empaquetar.sh` → `dist/An.zip` (Python 3.13 embeddable + win_amd64 wheels from `requirements.txt`, launched by `An.bat` → `pythonw.exe -m an`; copies the whole `an/` package). `./empaquetar.sh prueba` builds a minimal hello-window zip to test a corporate PC. Not yet tested on the target PC.

## Layout
- `an/nucleo/` — shared core: `tema.py` (color tokens `C` + ESTILO from the FigCraft design `docs/diseno/An_UI.figcraft`, `preparar_app` loads the bundled Inter/Sora in `fuentes/`, `icono_app`), `widgets.py` (`Tarjeta`, `tabla`, `llenar`, `con_vacio`, `ocupado`, `poner_nivel`…), `shell.py` (`Ventana`: header, sidebar, banner, toast, shortcuts, settings; `error_inesperado` → `errores.log`), `usuarios.py` (local user → area), `graficos.py` (`Barras`, `Linea`: QPainter charts with the `C` tokens, no dependencies).
- `an/radiologia/` — `generar_semana.py` (core, no GUI), `analisis.py` (pure functions), `paginas.py` (`Planilla` area), `plantilla_semana.xlsx`.
- `an/turnos/` — pure core (`dominio`, `db`, `reglas`, `solver`, `demanda`, `dotacion`, `puestos`, `capacitacion`, `recargos`, `flujo`, `cambios`, `analitica`, `exportar`) + UI (`paginas.py` = `Turnos` area, `ui_puestos.py`). Imports inside the package are relative.
- `an/__main__.py` — `AREAS` registry, user prompt, "Cambiar usuario" loop. `tests/<área>/`, `ejemplos/radiologia/`, `docs/`, `dist/` (ignored). Data next to the package: `turnos.db`, `usuarios.json`, `errores.log` (all ignored).

## Core contract
An area is a class with `NOMBRE`, `CLAVE`, `__init__(ventana)` and `secciones` (list of `(título, QWidget)` = sidebar entries); optional `cabecera`, `vacia`, `TAMANO`, `iniciar()`, `seccion_activa(i)`, drag/drop events, `cerrar()`. Areas talk to the shell through `ventana.avisar/notificar/ir_a/contar/mostrar_vacia/atajo/cfg`. Settings keys are prefixed with the area `CLAVE` (`radiologia/ultimo_archivo`). Never create a `QSettings("…","…")` directly: use `ventana.cfg` (org/app are set in `preparar_app`, so tests can redirect the default format). One look for every area: add rules to `ESTILO`, not per-area stylesheets.

## Radiología: roster requirements / agreed rules
See `docs/RADIOLOGIA.md` for the architecture notes. Essentials:
- Row 3 of `Cambios …` must hold full dates (format `d`); weeks are matched by exact date. Values are read with `data_only=True`, so the roster must have been saved by Excel.
- Contingencia, vacaciones, asignación de estudios and free-text notes stay blank (manual); full names everywhere; densitometría includes Sunday; `Z` and hemodinamia are not published. Unknown shift codes are reported, not published.
- Keep Spanish sheet names, headings and labels exactly as written. `~$…xlsx` are Excel lock files: ignore.

## Esterilización: agreed rules
- Pure core, Qt only calls it; the solver runs in a `QThread`. `asignacion` has two versions per month: `original` (published) and `cambios` (working copy; manual edits are `fijo`).
- Coverage comes from posts' demand rules (default seed: 4 day posts + Guardia noche ×2 Mon–Sat; Autoclave and Lavado + guardia on Sun/holiday; Ropa desirable). Restricted person: no nights, only post 3. Refuerzo is outside the solver.
- Hours: art. 165 CST average over N weeks (default 3) vs 42 h/week; unpaid pauses don't count. Legal figures are editable data — confirm with RR. HH./legal. Exports never overwrite (`v2`, `v3`…). Keep Spanish labels.
- Manual edits of the grid are audited: the UI asks permuta / cambio de servicio / ajuste and `cambios.py` writes `cambio_turno` (append-only; undo = anular) and `cambios.log`. Only permutas spend the per-person, per-period cupo `limite_permutas` (default 2; over it needs an approved exception). Undo/anular is all-or-nothing: if a cell was edited after the change, it refuses (`EditadoDespues`). After every manual change the toast lists only the *new* alerts (rules, coverage, posts left uncovered); it warns, never blocks.
- Personal requests (`solicitud` table, tab «Solicitudes»; types `libre` / `quiero` turno / `evitar` turno, priority normal/alta; `servicio` fixed `esterilizacion`) are registered by coordination only and are a **soft wish**: `solver.py` adds a per-day penalty (`solicitudes.W_SOL` 400 / 4000, below `W_FALTA`), never a hard constraint, so coverage and legal rules win. `solicitudes.evaluar` (pure) gives cumplida / parcial / no cumplida / fuera + a heuristic reason from the current grid; after generating, the toast lists up to 3 unmet.
- Analíticas section (read-only): `analitica.py` computes ausentismo, simultáneos, cobertura, cambios, horas extra (mes vs N semanas), recargos, equidad and banco de horas from existing tables (no migration); the UI only paints. Spec: `docs/superpowers/specs/2026-10-25-dashboard-analiticas-design.md` (all 3 deliveries done). «Costo» = horas equivalentes (there is no salary data); banco uses closed periods and movements only.
