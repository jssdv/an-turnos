**Goal:** `python -m an.web.migrar turnos.db --clinica N --area M` pasa una base SQLite existente a un área de una clínica en PostgreSQL, en una sola transacción, y comprueba que las cifras del núcleo salen iguales en ambos lados.

**Architecture:** Un solo módulo `an/web/migrar.py`. Abre el origen con `BD(ruta)` (ya aplica las migraciones v2–v7 de SQLite), copia cada tabla por la intersección de columnas (las de PostgreSQL menos `clinica_id`/`area_id`; las de `clinica_id`/`area_id` salen del alcance RLS), crea `periodo` desde las claves, ajusta las secuencias `GENERATED BY DEFAULT` y calcula `cifras(bd)` en ambos lados con las mismas funciones del núcleo. Si algo difiere, revierte la transacción y sale con 1. `--solo-verificar` repite solo la comparación contra un área ya migrada. No hay migración SQL nueva.

**Tech Stack:** Python 3.13, sqlite3, psycopg 3, pytest.

**Spec:** `docs/PLAN_WEB.md` (§3 modelo de datos, §6 Fase 2)

## Global Constraints

- Los ids del origen se conservan (colaborador, novedad, puesto, demanda, banco_mov, cambio_turno, solicitud) porque `persona_puesto`, `demanda.puesto_id`, `cambio_turno.celdas`, etc. los referencian. Tras insertar ids explícitos, cada secuencia se sube a `max(ya usado, máximo migrado)` sin leer filas de otras áreas.
- El área destino debe existir en esa clínica y **no tener datos de usuario** (colaborador, novedad, asignacion, puesto_dia, capacitacion, periodo_estado, cierre, banco_mov, asignacion_puesto, cambio_turno, solicitud, persona_puesto, periodo). Los catálogos que `crear-area` siembra (turno, puesto, demanda, tarifa, parametro) se reemplazan por los del origen.
- `cobertura` (tabla en desuso) no se migra. Las columnas del origen que PostgreSQL no tiene (`servicio` en `cambio_turno` y `solicitud`) se descartan: las da `area_id`.
- Las claves de periodo deben ser `AAAA-MM-DD/AAAA-MM-DD`; otra forma se rechaza con el mensaje de la clave (las claves no son datos personales).
- Datos reales (`turnos.db`) solo para una corrida local de aceptación. Los mensajes de diferencia nombran sección y periodo, nunca nombres ni valores. Las pruebas usan una base sintética creada en la prueba.
- Si el rol de conexión se salta RLS (superusuario en desarrollo), las lecturas de verificación se hacen con `SET LOCAL ROLE an_app`, como la API.
