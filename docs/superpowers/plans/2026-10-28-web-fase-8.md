## Decisiones

- **Una imagen, dos comandos.** La API y el trabajador comparten `servidor`; el comando lo pone Compose. Se instala `requirements-web.txt` + `ortools` + `openpyxl` (sin PySide6; `an.turnos` puro no lo importa).
- **Caddy sirve el front.** La API no sirve estáticos: `Caddyfile` con `handle /api/*` → `api:8000`, el resto `web/dist` con fallback a `index.html`. Dominio por `AN_DOMINIO`; `localhost` usa el certificado interno de Caddy.
- **Contraseña por `PGPASSWORD`, no en la URL.** `AN_PG_URL=postgresql://an_app@db:5432/an` y la clave entra por `PGPASSWORD` (libpq): evita codificar caracteres. La clave de `an_app` se fija con `deploy/crear_roles.sh` (idempotente) desde `AN_APP_CLAVE`.
- **Rol dueño = superusuario de arranque (`an_admin`)**, solo para `migrar`, `admin`, `respaldo`. Un rol `BYPASSRLS` no superusuario sería más estrecho, pero el contenedor `postgres` ya crea el superusuario y la migración inicial lo necesita para `CREATE ROLE`; se anota en `docs/seguridad.md` como riesgo aceptado.
- **Respaldo:** `pg_dump -Fc` → `age -R` (clave pública; la privada vive fuera del servidor) → archivo `an-AAAAMMDD-HHMMSS.dump.age` + `.cifras` (conteo y hash por tabla, calculados por `deploy/cifras.sql` como dueño). Retención por días configurable. Destino = carpeta montada (copiarla fuera del servidor es 👤: rclone/rsync a un bucket de la misma región).
- **Restauración probada:** `deploy/restaurar.sh` levanta un `postgres:16` desechable, descifra, `pg_restore`, recalcula `.cifras` y compara.
- **IP real:** ver Architecture; test con `ProxyHeadersMiddleware` en `tests/web`.
